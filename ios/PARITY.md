# iOS port status

This comparison uses upstream Android **2.0.1**, revision [`124e173`](https://github.com/the-geeky-couldron/waypoint/commit/124e173), and the iOS **0.3.0** contribution branch. The branch includes that upstream revision. Implementation and device verification are listed separately; full Android parity has not been established.

The [README screenshots](../README.md#ios-port-work-in-progress) and reported LiveContainer navigation result are from the earlier 0.2.0 preview. They show destination selection in Night City and Los Santos. They do not verify the changes in 0.3.0.

Renaming preserves identity, address and coordinates and updates recent entries. | Core tests cover validation and coordinate preservation. | Camera following | Map gestures pause following. During navigation, following resumes eight seconds after the gesture ends; Locate resumes immediately. Destination previews stay framed until another action. | Clock-based tests cover gesture duration, timeout and manual resume. Device gesture and heading-up camera checks remain open. |
| Location and heading | Core Location supplies the fix. Course/compass arbitration uses Android's walking/driving speed thresholds, hysteresis, accuracy checks and freshness limits. A watchdog restarts stalled updates. | Core tests cover stale/noisy readings and source changes. Core Location owns provider selection; Android GNSS satellite counts and provider arbitration have no direct iOS counterpart. Permission changes and host-specific behavior need device checks. |
| Guidance and rerouting | Ferrostar uses the active Android waypoint, arrival and deviation thresholds by mode, with its five-second/50-metre recalculation guards. Failed reroutes retain the current route and show a message; stopped sessions reject later results. | The comparison uses FerrostarGuidance.kt, not the older unused ReroutePolicy. The native parser suite is included. Wrong turns, arrival and outages still need controlled iPhone checks. |

| Quests | Every idle HUD opens a native local task list. ## Platform scope and open differences

- iOS Quests currently omit photo/character attachments, notification reminders, avatar frames and story chapters. The task, focus and reward data stay local. There are no background quest alerts to interrupt guidance. These differences are proposed for review, not agreed exceptions or completed Android parity.
- A share extension, default-navigation registration and CarPlay are absent. Paste/import and destination sharing work inside the phone app. Android Auto has no literal iOS copy; CarPlay needs separate implementation and entitlements.
- iOS opens upstream release pages and leaves signing/refresh to the installer. It does not reproduce Android's APK downloader, signature checks or package installation.
- Locked-screen speech, long sessions, battery use, reduced accuracy and installer refresh remain unverified. The earlier LiveContainer report does not establish those behaviors for this build.

## Before merge

Run the native Ferrostar parser/resource tests and simulator UI suite on the final revision. Record controlled iPhone checks for spoken turns, wrong-turn rerouting, arrival, permission changes, locked/background guidance and saved-place persistence. Review the added worlds on an iPhone, including compact screens, large text and VoiceOver. Agree on the remaining Quests and platform scope with the maintainer.
